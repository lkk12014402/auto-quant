aqa · auto-quant · RFC 0001
Reproducible Quantization
as a Phase & Artifact Contract
每一次 aqa run 都是一台确定性状态机：九个相位、每个相位固定的输入 → 过程 → 输出 → 产物 → 产物内容 schema。产物即契约，契约即可复现、可恢复、可复用。
P0–P4 + S3 shipped Hyperloom-inspired session = manifest · state · events aqa inspect = artifact gate resume-safe
← / → · Space · click edges
Motivation

01从「不可控的 agent 跑批」到「可复现的状态机」

优化前：中间产物散落在 executor log / transcript 里，结构不固定、知识无法复用、session 无法 resume。优化后对标 Hyperloom 的六根支柱，把过程结构化、固定化。
支柱Hyperloom 对应aqa 落地
S1 Session tripletsession/manifest·state·eventsaqa/session/{manifest,state,events}.py
S2 Resumemanifest 缺失即拒绝should_skip() + load_session_manifest()
S3 Phase machine + guard相位→允许动作aqa/session/actions.py + requant loop
S4 Recipe KB验证过的配方复用aqa/agent/recipe_kb.py
S5 Critic / PolicyGate自愈 + 策略护栏aqa/agent/{critic,policy_gate}.py
S6 Patch / CLI 上行改动可回收capture/publish-patch（部分）

一句话设计原则

把「agent 做了什么」从不可审计的对话里搬进有序、机器可读的产物流。

  • 每个相位的产物提前约定（layout.yaml 为单一事实源）。
  • 产物带 schema_version / run_id / created_at，可 diff、可校验。
  • aqa inspect 把「产物是否齐全/合法」变成一道硬门。
  • 没有产物 = 相位没完成；resume 据此决定跳过还是重跑。
能把每个相位的输入/输出说清楚，代码才稳。本 deck 即该规格。

前置（确定性）

ANALYZE · ENV · PLAN —— 只读 config.json、冻结软硬件栈、打开 session 三件套，不碰权重、不联网、不占卡。

运行时（条件）

Lifecycle contract

03每个相位的通用生命周期：enter → run → done

相位不是自由代码块，而是带前置/后置条件的事务。守卫、留痕、产物校验对所有相位统一生效。

统一时序

with session.phase(Phase.QUANT):     # enter
    guard = allowed_actions_for(phase) # S3 precondition
    artifact = run_phase(...)          # 过程
    write_phase_artifact(artifact)     # 固定产物
# done: state.phases[QUANT]=DONE,
#       events += phase_done
  • enter → state.phase=cur, status=RUNNING, events += phase_enter + phase_transition{from,to,allowed,loopback}
  • run → 执行该相位动作（受 S3 守卫），shell 出 auto-round / lm_eval
  • done → 写产物、status=DONE、events += phase_done；异常 → FAILED + phase_fail

三条不变量

  • Precondition：进入相位前，S3 校验「本相位允许的动作」与「转移是否合法」。
  • Postcondition：相位结束必须留下其约定产物（见 layout.yaml）；否则 resume 视为未完成。
  • Idempotent resume：should_skip(phase) = state.is_done(phase) AND artifact_present。两者缺一即重跑。
产物 = 相位的「收据」。有收据才算做完，才可被下游/resume 信任。

Phase · runtime · if gate configured

10GATE —— 裁决 GO / NO-GO & 有界回环触发点

Input
eval 结果 + baseline + gate 配置（max_accuracy_drop / min_accuracy / significance / alpha）
Process
evaluate_gate() → GO / NO-GO / INCONCLUSIVE；若 gate.requant.enabled 且非 GO → 触发有界 re-QUANT 回环
Output
gate.json；state.gate；回环时 requant/cycle_n/ + 晋升 + .requant_done
Actions
∅ Coordinator-reserved
GATE 是唯一允许「GATE→QUANT」回退边的相位；EVAL→QUANT 非法——不许绕过裁决私自重做。

gate.json

{
  "verdict":"GO", // GO | NO-GO | INCONCLUSIVE
  "reasons":[
    "mean drop -1.1% ≤ 2.0% threshold",
    "gsm8k within significance band (α=0.05)"
  ]
}

动作集为空：裁决与重试由 Coordinator 持有，agent 不能在 GATE 内自行发起量化/评估。

S3 · precondition guard

15相位动作守卫 —— allowed_actions_for(phase)

aqa/session/actions.py：纯函数、可单测。把「某相位能做什么、能往哪转」固化成契约，Coordinator 据此守卫。

契约 API

  • allowed_actions_for(phase) → 该相位动作集
  • is_action_allowed(phase, action)
  • is_transition_allowed(from, to) —— 沿计划前进 + 唯一 GATE→QUANT 回退；EVAL→QUANT 非法
  • is_loopback(from, to) · action_contract()

守卫语义

session.guard_action(action, phase=current, **ctx)
# 记录 phase_action_denied + decision
# guard_enforce=True → 抛 PhaseActionDenied
# guard_enforce=False → advisory（仅留痕）

配置开关

agent.action_guard:
  enabled: true   # 记录 denied 事件
  enforce: false  # 默认 advisory，不阻断
为什么默认 advisory？外部 agent 作为 proposer 时，先观测 + 留痕，不贸然阻断已在跑的流程；团队信任契约后再切 enforce。

守卫注入 agent 提示

build_fix_prompt(..., allowed_actions) 渲染「本相位允许的动作」块；fix-loop 两处调用点都带上 → agent 自我约束在契约内。

Reproducibility · resume

17Resume 语义 —— 跳过还是重跑？

跳过判据

should_skip(phase) =
    state.is_done(phase)
    AND artifact_present(phase)
  • 两者都满足 → 标 SKIPPED，emit phase_skip，复用已有产物。
  • status=DONE 但产物缺失（半成品 / 被清理）→ 重跑，不信任状态。
  • manifest.json 缺失 → load_session_manifest 抛错，拒绝 resume。

为什么「产物在场」是硬条件

状态可能被写坏/中断，但产物是相位真正完成的物证。以产物为准，resume 永不基于谎言前进。

已知边界

  • ssh resume：远端执行中断 / 连接丢失时的续跑仍是待完善项（规划中）。
  • 并发写同一 run_dir 未加锁 —— 约定单 writer。
宁可响亮失败，也不伪造恢复 —— 与 Hyperloom 的 resume 前置一致。
Single source of truth

18产物契约 layout.yaml & aqa inspect 硬门

aqa/report/layout.yaml 是所有产物的唯一事实源：每条 {path, kind, phase, when, sink, desc}；when 条件由 layout.py:_conditions 解析。
字段含义
path产物相对路径
kindjson / dir / jsonl / raw
phase归属相位（"" = session 级）
when出现条件（quantize / baseline / gate / session...）
sink是否随结果分发
desc人类可读说明
改产物先改 layout.yaml —— 契约先行，代码跟随。

aqa inspect = 产物门

把「本次 run 该有的产物是否齐全 / schema 是否合法」从主观检查变成一道可自动化的门：

  • 按 layout.yaml + 本次 when 条件，枚举应有产物。
  • 缺失 / schema_version 不符 / 字段缺 → 失败。
  • CI / fix-loop 可挂此门，产物不合契约就不放行。

配合相位 postcondition：相位结束→产物落盘→inspect 可验证→resume 可信任，闭环。
