# Example: a full quantize → evaluate → gate run

This walks through `examples/run_5000.yaml`, an end-to-end config that
quantizes **Qwen/Qwen3.5-9B** to **MXFP8** on a
direct RTX 5000 Pro CUDA host, agent-optimize the recipe, evaluate on
`piqa,hellaswag,mmlu,gsm8k` against the bf16 baseline, and gate the result.

## The command

```bash
python3 reserve_and_login.py \
    --model Qwen/Qwen3.5-9B --scheme MXFP8 --method MODEL_FREE \
    --user kaokao --server 5000pro_7cards --gpus 6 \
    --export-format llm_compressor \
    --agent-optimize --agent-context @xpu_context.txt \
    --eval-tasks "piqa,hellaswag,mmlu,gsm8k" --eval-baseline \
    --gpu-dockerfile local
```

## Flag → config mapping

| `run_5000.sh` flag / env | `run_5000.yaml` field |
| --- | --- |
| `--model Qwen/Qwen3.5-9B` | `model` |
| `--scheme MXFP8` | `quant.scheme` |
| `--method MODEL_FREE` | `quant.method: model_free` |
| `--export-format llm_compressor` | `quant.export_format` |
| `--eval-tasks "piqa,..."` | `eval.benchmarks` |
| `--eval-baseline` | `eval.baseline: true` |
| `--agent-optimize` | `agent.optimize: true` |
| `--agent-context @xpu_context.txt` | `agent.context: "@gpu_context.txt"` |
| `AGENT_TIERS="opus"` | `agent.tiers: [opus]` |
| `--server 5000pro_7cards` (direct, no jump) | `executor.type: ssh` + `executor.ssh.host` |
| `--gpus 6` | `executor.ssh.gpus: "6"` |
| `--gpu-dockerfile local` | `executor.image.dockerfile: local` |
| NGC base image | `executor.image.gpu: nvcr.io/nvidia/pytorch:26.01-py3` |
| `LOCAL_HTTP(S)_PROXY` | `executor.proxy.*` |
| `LOCAL_RESULTS_DATASET` | sink `hf_dataset.repo` |
| `LOCAL_RESULTS_HF_TOKEN` | sink `hf_dataset.token_env` |

The implicit `reserve_and_login.py` env chain becomes one declarative file plus a
handful of named environment variables — **no secret is stored in the YAML**, so
it is safe to commit.

## Secrets: put them in a git-ignored `env.sh`

`run_5000.sh` exports credentials inline. Here they are read only from the
environment variables the YAML names, so keep them in an un-committed file:

```bash
# env.sh  (add to .gitignore)
export GPU_HOST='root@10.239.11.55'        # the direct RTX 5000 Pro host (root login!)
export GPU_SSH_PASS='intel@123'            # password for GPU_HOST (never in YAML)
export SSHPASS="$GPU_SSH_PASS"             # sshpass reads SSHPASS from env

export HF_TOKEN='hf_...'                   # model download
export LOCAL_RESULTS_DATASET='lvkaokao/lb_local'
export LOCAL_RESULTS_HF_TOKEN='hf_...'     # dataset write token

export LOCAL_HTTP_PROXY='http://proxy-ir.intel.com:912'
export LOCAL_HTTPS_PROXY='http://proxy-ir.intel.com:912'

export MINIMAX_API_KEY='...'               # if a non-opus tier is enabled
export COPILOT_GITHUB_TOKEN='...'          # required for the opus tier
```

## Run it

```bash
cd autoquant-agent
pip install -e '.[ssh]'          # paramiko for remote dispatch
source env.sh

# 1. Check the config resolves (env-expansion + schema):
aqa validate examples/run_5000.yaml

# 2. See exactly what will run remotely, without touching the host:
aqa run examples/run_5000.yaml --dry-run
#   -> [CMD] sshpass -e ssh -o StrictHostKeyChecking=no kaokao@... 'aqa run run.yaml'

# 3. Real run:
aqa run examples/run_5000.yaml
```

## What happens on a real run

1. **executor=ssh** connects to `GPU_HOST` (direct; no jump hops) with paramiko,
   ships this repo as a tarball into an isolated per-run dir on the host, and
   builds the local CUDA Dockerfile (`docker/gpu.dockerfile`) on
   `nvcr.io/nvidia/pytorch:26.01-py3`.
2. **container bootstrap** installs `aqa` + the quant/eval stack (auto-round,
   lm-eval) against the NGC base's torch/CUDA, then runs `aqa run` **inside** the
   container with `executor.type=local` and `--gpus device=6`.
3. **agent-optimize** analyses the model and produces the MXFP8 quant recipe.
4. **quantize** runs auto-round `model_free` and exports `llm_compressor` format.
5. **baseline eval** runs the bf16 original; **eval** runs the MXFP8 checkpoint on
   `piqa,hellaswag,mmlu,gsm8k` via the vLLM backend. With `eval.lm_eval.group: true`,
   `piqa+hellaswag+mmlu` run in **one** `lm_eval` call (one model load) and `gsm8k`
   runs separately (it needs `--apply_chat_template --fewshot_as_multiturn`).
   `eval.lm_eval.model_args` (e.g. `enable_thinking=False,reasoning_parser=qwen3`)
   are appended to the vLLM `--model_args`.
6. **gate** compares them — NO-GO if MXFP8 drops more than `0.02` vs baseline.
7. **fix_loop** root-causes and retries any failing phase; auto-round fixes are
   captured as a patch (`agent.patch.capture: true`).
8. **sinks** write results to the mounted per-run dir on the host and push a
   record to the HF dataset. Results stay under
   `~/aqa-runs/<run_id>/repo/results/<run_id>` on the GPU box.

> **Remote path status.** `executor.type=ssh` is fully wired for a **direct or
> single-jump** host: it stages the repo, builds the image, and streams the
> container run over SSH. `--dry-run` prints the exact dispatch script + the
> derived in-container `run.yaml` without connecting. Secrets reach the container
> only through a locked-down `--env-file` (never the config, never `ps`). Deeper
> multi-hop chains and Intel reservation/topology live in the optional
> `aqa-executor-intel` plugin. paramiko is required: `pip install -e '.[ssh]'`.
